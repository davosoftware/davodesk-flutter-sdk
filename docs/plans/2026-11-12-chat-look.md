# Chat look Implementation Plan (Flutter SDK)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. The owner chose inline execution (executing-plans), no subagents.

**Goal:** the SDK's bot replies show the brand's logo, the bot's name and ✦ on what the AI wrote; its corners follow DavoDesk unless the app's code sets them; and a look saved in DavoDesk reaches an open app the next time support opens.

**Architecture:** the models read two new API fields (`ai_written` on messages, `appearance.corners` on the channel). The view models turn runs of bot messages into bubbles with a head; `MessageBubble` draws the head. The theme takes corners from code, then the channel, then rounded. The client forgets its cached channel config each time support opens.

**Tech Stack:** Flutter (3.47 floor, `material_ui`, primary constructors), `flutter_test`.

**Spec:** [`docs/specs/2026-11-12-chat-look-design.md`](../specs/2026-11-12-chat-look-design.md) (a copy of the approved design in `davodesk-apps`; mockup v7 beside it). The API, widget and DavoDesk part is `davodesk-apps/docs/plans/2026-11-12-chat-look.md`, whose Tasks 1 and 2 add the fields this plan reads.

## Global Constraints

- The bot's name is the channel config's `ai_agent_name` (already "DavoDesk AI" when unset). Never built from the brand's name.
- ✦ only where a message's `ai_written` is `true`; a message without the field (an older API) shows no ✦.
- Corners: the app's `DavoDeskTheme.corners` if set, else the channel's `appearance.corners`, else rounded. Square means radius 0, as `DavoDeskCorners.square` already does.
- A look saved in DavoDesk shows the next time support opens, with no app restart.
- Human agents' and the customer's bubbles do not change.
- Read the current Flutter and Dart docs before changing an API you are unsure of (the owner's rule, 2026-11-09). No new dependency.
- Commits under the owner's identity, no co-author trailer. The example app's emulator run needs the owner's OK.

## Review Focus

1. **An API that sends neither field yet** (deployed before `davodesk-apps` Tasks 1–2): no ✦, rounded corners, nothing throws. Pinned in Task 1.
2. **A brand without a logo:** the head shows the brand's initial on its colour. Pinned in Task 2.
3. **The app's code sets corners and the channel says otherwise:** the code wins. Pinned in Task 3.
4. **Support opened twice in one app session after a look change:** the second opening shows the new look, and one opening still reads the config once. Pinned in Task 4.
5. **A ticket's history after a hand-off:** its bot messages head their runs the same way as the live chat. Pinned in Task 2.
